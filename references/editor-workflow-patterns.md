# Editor application workflow patterns

Use this guide for a functional validation editor, not as an SDK-wide requirement for every product. Apply only the sections implicated by the requested feature and its direct dependency closure; the presence of the editor does not make unrelated workflows part of validation.

When this default editor workflow is selected, do not use the optional first-media placement described for an empty project in [project-xml-and-persistence.md](project-xml-and-persistence.md); imports populate the asset library only.

## Media library and placement

- Accept multiple supported video, image, and audio files. Register each WebLocal resource independently, report per-file failures together, and do not add imports to the Timeline automatically.
- Keep stable asset, track, and item IDs separate from mutable SDK indexes. A catalog item may be added repeatedly.
- Add at the playhead. Check only the highest same-type user track. Reuse it when its `[in, out)` ranges do not overlap the new item; otherwise append exactly one new same-type track. Do not search lower tracks for free space. Adjacent boundaries do not overlap.
- Keep SDK track order, creation order, and visual row order explicit. In the default editor, render non-media virtual lanes above media tracks, video tracks above audio tracks, and newly created video/audio tracks at the top of their own type group. A newly created caption, sticker, filter, effect, or adjustment lane appears at the top of all non-media lanes. Reusing a track or lane never changes its visual order. Preserve stable UI IDs, creation order, and labels instead of deriving them from a reversed row index.
- Apply the same highest-lane `[in, out)` policy to caption, sticker, filter, effect, and adjustment virtual lanes. Timeline-level timed objects remain separate from SDK media tracks, and each product kind has its own collision namespace.
- Maintain separate filter, effect, and adjustment virtual-lane namespaces even though all contain `NvsTimelineVideoFx`. Never place different product kinds in the same logical lane or treat their equal time ranges as a conflict. One adjustment item owns a synchronized stack of SDK effects but occupies one logical lane interval.
- Keep SDK video track 0 as a hidden system base with `:/footage/transparent_black.png`. Exclude it from UI numbering and collision checks. After any content add, Trim, Split, delete, speed, caption, sticker, filter, effect, or adjustment change, set it to at least one frame and otherwise to the maximum content out-point.
- Use 4 seconds for still-image imports and 3 seconds for default caption/sticker instances unless the user requests another value.

## Default catalogs

- Caption: show `默认文本` plus test resource `default-caption-style` (`E30D10CF-6693-4BDD-BE66-418F86BB1578`). Create content `默认文本`; apply the style only for the styled card.
- Sticker: show test resource `default-animated-sticker` (`A1509C3D-7F5C-43CB-96EE-639ED7616BB7`).
- When requested, show Filter and Effect as separate package catalogs and Built-in as a separate source catalog. A packaged filter and packaged effect both install as `NvsAssetPackageTypeEnum.VideoFx`; a built-in card passes its verified SDK name instead of a package ID.
- Read URLs and test-only licensing metadata from [test-resources.json](test-resources.json). Never promote either package to a production default.
- Begin package preparation when its panel first opens. Show the card immediately; disable add-to-track while loading; show retry after failure. Always delegate installation to the session coordinator—component guards are supplementary, not concurrency control.

## Selection and commands

- Maintain one `SelectedTimelineItem` union for media, caption, sticker, filter, effect, adjustment, or transition. Identify a transition by stable track ID plus source-clip index, render its marker at the SDK boundary, and clear the selection if that queried transition no longer exists. Selecting a Timeline item opens its matching inspector when it has one; clicking Timeline blank space clears it.
- Model a product-level lyrics lane separately from ordinary caption lanes even though its SDK objects are timeline captions. Do not allocate lyrics through ordinary caption-lane packing or create an SDK video track for that UI row. When the product requires one lyrics lane, reuse it for every lyrics caption, keep it at the specified UI edge, and remove only the empty UI lane after its final caption is deleted. Treat overlap checks as half-open intervals `[inPoint, outPoint)` so adjacent lyrics are allowed.
- Keep mutation rejection feedback visible independently of the current selection or inspector body. Collision, authorization, package, and SDK-return-value failures must remain visible while an item is selected, and a rejected mutation must not change editor state or create a history entry.
- Put delete only in the Timeline control bar. Disable it without selection, during structural edits, or during crop/mask gestures. Delete media without closing gaps. Delete a selected transition with `setBuiltinTransition(sourceClipIndex, '')`, verify `getTransitionBySourceClipIndex()` returns no object, then clear selection and refresh the retained preview position.
- Split any selected media, caption, sticker, filter, effect, or adjustment item only when the playhead is strictly inside it and each side retains at least one frame. A transition is a boundary object and never participates in Split or Trim. Wrap `splitLogicalTimedItem()` from [timed-object-operations.ts](../assets/samples/timeline/timed-object-operations.ts) with `mutateAndPreservePreview()`; its `createRight` adapter must preserve the concrete caption, sticker, filter, or effect properties, lane, and creation order, while the helper rolls back both sides on failure. Treat an adjustment stack as one logical item and use [timeline-adjustment-workflow.ts](../assets/samples/effects/timeline-adjustment-workflow.ts) to split every member at the same point.
- When the product requests an inserted freeze-frame command, place it in the Timeline control bar and enable it only for the supported selected video/playhead state. First confirm duration, selected-track versus global ripple behavior, post-insert selection, and repeated-click behavior. For selected-track insertion, use [insert-freeze-frame.ts](../assets/samples/video/insert-freeze-frame.ts); keep the created segment's stable UI ID separate from its mutable SDK index and leave unrelated audio, caption, sticker, and effect lanes unchanged.
- Keep video controls for speed, volume, rotation, scale, X/Y, and reset; image controls omit speed/volume. Audio controls include speed, volume, fade-in, and fade-out; when managed audio processing is requested, add loudness/noise-suppression controls and a separate single-select preset view using the schema and lifecycle in `audio-editing.md`.
- Treat one pointer/keyboard input gesture as one logical mutation transaction. Snapshot the SDK state and retained Timeline position once at gesture start, throttle live preview writes as needed, then commit one history entry and one final seek at gesture end.
- Treat each managed audio-FX toggle or preset selection as one history entry. Persist the SDK-read managed state in snapshots; on undo/redo restore loudness, noise suppression, then preset. After audio Split, apply the same managed snapshot to both SDK child clips and verify both by reading their FX stacks. Preserve unrelated audio effects throughout these operations.
- Serialize committed property edits with playback commands. A pointer-up/blur speed commit must finish its stop/readiness/mutation/seek cycle before a following Play command; deduplicate pointer-up and blur commits so one gesture cannot create two history entries or race playback.
- Keep constant-speed and documented curve-speed controls in the video inspector. A speed edit changes the selected clip's frame-aligned out-point and downstream duration state; the ruler scale, Timeline zoom, and seek coordinate system remain independent.
- Put one keyframe toggle after each supported transform group. Position and scale are paired X/Y groups; opacity and rotation are scalar groups. Disable toggles outside the selected item's `[in, out)` range, show the current interpolated value while seeking, and aggregate multiple groups at one absolute time into one non-blocking diamond marker with a group-count tooltip.
- Persist video animation slot kind, package ID, scope, and clip-local range in application history. After Trim, Split, or speed edits, re-anchor and cap animation ranges for each resulting clip; before undo/redo restoration, verify all referenced packages are still `Ready` so a failed restore does not partially clear the current animation.
- Persist inserted freeze-frame enabled state, source Trim position, duration, muted-audio invariant, stable ID, and selection in application history. Restore a freeze segment from its valid source-frame Trim range, re-enable freeze and audio disabling, extend its Timeline out-point, then verify the read-back state before seeking. Split, same-track movement, freeze creation, property copying, duration synchronization, and selection update are one history entry; any failure restores the complete pre-command snapshot.

## Trim and preview invariants

- Every trimmable Timeline item uses the same collision invariant: clamp its left edge to the previous same-track or same-lane item's out-point, clamp its right edge to the next item's in-point, retain at least one frame, and allow equal `[in, out)` boundaries but never overlap. Apply the clamp both in pointer/keyboard preview code and again in the editor mutation API; UI validation is not a trusted boundary.
- Normal media Trim uses track `changeInPoint`/`changeOutPoint`. Respect source Trim limits and use the SDK's actual returned position. Use [editor-media-trim.ts](../assets/samples/timeline/editor-media-trim.ts) for collision prevention and the required preview refresh.
- Caption, sticker, filter, effect, and adjustment Trim uses the matching timed-object `changeInPoint()`/`changeOutPoint()` calls. Clamp against zero, Timeline duration, one frame, and previous/next items in the same product kind and virtual lane; then store and validate the actual SDK-returned range. For an adjustment item, mutate every stack member and reject or roll back a result whose member ranges diverge.
- A still image has no earlier source frames. To drag its left edge earlier, remove and recreate it at the requested Timeline in-point with source trim 0 and duration equal to the old out-point minus the new in-point. Restore supported clip volume, property transform, crop, mask, and stable UI identity.
- Before every visible add, delete, Trim, move, undo, redo, or completed property gesture, call `getTimelineCurrentPosition(timeline)` and retain its return value in a local variable at transaction start. After mutation and duration synchronization, clamp that retained value to the new Timeline duration and seek there. Intermediate gesture previews reuse that retained value and do not create their own history entries or final seeks. This is an SDK read, not a second application-owned playhead. Do not use the clip in-point as an implicit refresh target; another selected-item in-point or a position read only after mutation is equally invalid.

## Thumbnails and cleanup

- Generate several cancellable local icon requests across video duration and cache them by asset ID. Retain a cover fallback when a task fails.
- Map each visible tile center through the clip source Trim range, choose the nearest cached source frame, and recompute count from rendered width divided by 72 px. Split and Trim then naturally produce distinct frame ranges.
- Cancel outstanding thumbnail tasks, unregister WebLocal files, revoke Object URLs, dispose the package coordinator, and remove owned SDK FS temporaries when the editor session ends.
