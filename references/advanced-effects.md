# Advanced effects

Crop and masks are separate workflows. Use `assets/samples/effects/crop.ts` for NDC Crop boundaries, insertion before regional Raw FX, pixel-aspect-aware crop-box calculation, and anchor-preserving property transforms.

Classify the mask owner before calculating a region. The two coordinate models are not interchangeable:

| Owner | Origin and coordinates | Required sample |
| --- | --- | --- |
| `NvsVideoFx` Raw FX on an `NvsVideoClip` | Displayed source-video center; normalize against the current source-video view box and inverse its rotation/flips | `assets/samples/effects/video-mask.ts` |
| `NvsTimelineVideoFx` or `NvsTimelineCaption` | Timeline center/canonical coordinates, or LiveWindow view coordinates converted by `mapViewToNormalized()` | `assets/samples/effects/timeline-mask.ts` |

Both owner-specific samples cover line/mirror/ellipse/rectangle/rounded-rectangle/heart/star regions. Use `cornerRadiusRate` in `[0, 1]`; `0` is a straight rectangle and `1` reaches the maximum radius of half the shorter side. [video-mask.ts](../assets/samples/effects/video-mask.ts) derives the laid-out timeline image through LiveWindow canonical mapping instead of assuming the full canvas is the timeline image, then inverse-maps video rotation and negative-scale flips. Use `createVideoRectMaskRegionFromViewRect()` for a rectangle drawn in LiveWindow view coordinates instead of rebuilding that conversion in application code. Never pass a video-local region to a timeline owner, or a timeline region to a Raw video effect, without rebuilding it through the correct adapter.

For an ordinary video mask, the verified default is a video-clip Raw built-in `Mosaic` FX configured with `setRegional(true)`, `setIgnoreBackground(true)`, and `setFloatVal('Unit Size', 0)`. Serialize the normalized regions into `NvsVectorVal<NvsRegionInfo>` and call `setRegionInfos()`; use `setInverseRegion()` for inversion. A non-zero Mosaic unit size or `Gaussian Blur` is an explicitly requested presentation variant, not the default shade mask.

`assets/samples/effects/mask-region-io.ts` only serializes an already-normalized region and intentionally does not select a coordinate system or effect. It retains the SDK-level `Mask Generator` ARBDATA branch solely for an explicit user request to try that built-in after the target runtime has concrete rendered-output evidence. API/declaration presence is not sufficient validation and must never make `Mask Generator` the default. In that explicit branch, pass exactly one `NvsRegionInfo` through `Region Info`, including `setArbitraryValAtTime()` for keyframes; ordinary regional effects use `setRegionInfos()` or `setRegionInfosAtTime()` with a region vector.

Use `assets/samples/effects/text-mask.ts` for the Web 3.16.0 `Region Storyboard Description String` text-mask format, required microsecond-to-millisecond conversion, and transactional `addVideoTextMaskEffect()` creation/rollback. Shape masks and text masks using an already available SDK font require no model or material package. Treat a requested custom font as an external input: register and verify it before using its family name, and never invent a fallback family.

Treat one managed clip mask as one application-owned transaction. Persist its clip identity, kind, source view rectangle or text storyboard inputs, inverse flag, feather width, and rectangle corner radius; keep the returned `NvsVideoFx` only as the live-session handle. To replace a managed mask, create and fully configure the new effect first, remove the old owned effect only after creation succeeds, and remove the new effect if old-effect removal fails. Restore the persisted recipe after Split, recreation-based still-image Trim, undo/redo, or project load. On cancellation, selection change, failure, and teardown, remove only the owned effect and discard uncommitted gesture state.

Before add, replace, reset, or remove, retain `getTimelineCurrentPosition()` and stop playback. Await `streamingEngineReadyForTimelineModification()` before structural mutation, check `appendRawBuiltinFx()` and `removeRawFx()` results, then clamp and seek the retained position to refresh the connected LiveWindow. Static API presence cannot validate the effect parameter name or rendered region. In one initialized browser session, render ellipse, straight rectangle, intermediate and maximum corner radii, text containing non-ASCII/XML-special/newline content, inverse on/off, transformed or flipped clips, reset/removal, and cleanup. Report any unobserved rendered case as `pending-user-runtime`.

Use [human-detection.ts](../assets/samples/advanced/human-detection.ts) for shared model/data lifecycle, [human-segmentation-keyer.ts](../assets/samples/advanced/human-segmentation-keyer.ts) for background segmentation with `Object Stroke`, [ar-scene-beauty.ts](../assets/samples/advanced/ar-scene-beauty.ts) for documented `AR Scene` beauty/makeup parameters, [master-keyer.ts](../assets/samples/advanced/master-keyer.ts) for chroma keying and untreated-frame color picking, [particle-effect.ts](../assets/samples/advanced/particle-effect.ts) for emitter-controlled packages, and [auto-tone.ts](../assets/samples/effects/auto-tone.ts) for frame grabbing and tone mapping. Portrait mode remains gated on matching detection models and face data.

This domain includes particles, AR scene manipulation, masks/regions, chroma or master keying parameters, human detection, face information, and auto-toning. Most capabilities depend on a particular effect/package/model and cannot be activated by a generic call sequence.

Use capability detection first. Relevant entry points include `NvsFx.getARSceneManipulate()`, `getParticleSystemContext()`, region-info setters/getters, particle emitter controls, and `NvsStreamingContext` human-detection initialization/setup/close methods. Query the exact symbol and its callbacks before implementation.

Gate material packages, model files, licenses, effect parameter schemas, GPU/browser capability, and customer consent for any face/human processing. Models and materials are never bundled with this Skill. Do not downgrade to a different effect or upload user media to an external service without explicit authorization.

Keep model lifecycle paired. Write every customer-provided model/license/data file into SDK FS first. Initialize the first model with `initHumanDetection()`, then extensions with `initHumanDetectionExt()`, then call `setupHumanDetectionData()` for matching data files. The model-to-feature bitmask and data-to-type mapping must come from the customer's matching SDK/model delivery; do not infer either from a filename. Close human detection only when the owning feature ends and no other editor session shares it.

For background segmentation, use `NvsHumanDetectionFeatureEnum.SegmentationBackground` only when the supplied model delivery explicitly maps to that feature. Add clip Raw built-in `Object Stroke` with `Input Is Segmented = false` and `No Background = true`; optionally expose `Stroke Type`, `Stroke Color`, `Stroke Width`, and `Stroke Offset From Object`. The reference editor and a rendered Web 3.16.2 check support `Solid Line`/`Dash Line` and UI ranges `0..30` for width/offset, but the 3.16.0 API surface does not document this built-in parameter schema. Require target-source evidence plus getter round-trip and rendered-frame validation before treating it as compatible. Use `BuddyHostVideoFrame` seek/playback flags only in the detection-enabled preview session. Remove all owning `Object Stroke` effects before releasing the shared human-detection session.

For `Master Keyer`, treat effect replacement as a transaction: capture the previous parameters, remove duplicate owned instances, write the full requested schema, verify getters, and restore the previous effect on failure. An eyedropper must sample an untreated frame: stop playback, preserve the SDK Timeline position, temporarily remove `Master Keyer`, seek and await the unkeyed render, sample `getPixelColor()` in bounded CSS-pixel view coordinates, then restore or commit the effect at the preserved position. Make commit one application-history operation; cancellation, selection changes, and teardown restore the original effect without history.

The editor source loads face landmark/action, avatar, eye-contour, background-segmentation, and sky-segmentation models, followed by FakeFace, Makeup2, AdvancedBeauty, and FaceCommon data. This is evidence for ordering only, not a distributable or universal file list. AR Scene makeup layers additionally require Ready makeup packages; LUT parameters require an existing SDK FS LUT. Treat absent model, data, license, LUT, or package as `missing-external` and stop before creating the effect. Remove every owning AR Scene effect before disposing the shared human-detection session.

Validate capability/authorization, package/model integrity, initialization result, detection callback/data, parameter round-trip, rendered frame, and cleanup. If the requested combination lacks evidence, provide individual API descriptions and state that the combination is unverified.
